# Reliability contracts

The historical implementation was inspected at `6fe567a61a7391b27166dbac0583bc0be833f8e7`. The table separates implemented mechanisms from the test evidence for each property. The checks are repository engineering verification. The platform has no independent attestation of external execution.

| Property | Implementation and trust boundary | Existing invariant tests | Gap or limit |
|---|---|---|---|
| Logical identity survives retry | `agent/persistence.py` derives the proposal from execution, turn and position, and the write ID from the proposal. Trusted host code signs MCP metadata in `mcp/context.py`. | `test_interrupted_write_resume_fresh_host`, `test_hard_restart_after_eligible_committed_write_preserves_attribution` | A new agent decision can deliberately create a new logical operation. Similar arguments alone do not imply duplicate delivery. |
| Authorization precedes replay | `BoundContext.invoke` holds the sandbox lifecycle lease and verifies the incarnation. `OpsDeskService._operation` checks tenant, actor, tool permission and approval before receipt lookup. | `test_unknown_and_forged_tenant_actor_rejected`, `test_cross_tenant_and_absent_records_are_indistinguishable` | Trusted host and database ownership are outside this boundary. Add authorized cross-tenant key reuse and denied replay tests. |
| Transactional deduplication | `OpsDeskService._receipt` locks the sandbox identity row before a scoped receipt lookup. Canonical validated arguments must match. Transaction commits receipt, task and audit together under PostgreSQL. | `test_idempotent_create_update_and_conflicting_reuse`, `test_concurrent_retry_safety_over_protocol`, `test_failure_after_domain_write_and_receipt_rolls_everything_back` | All writes in one sandbox serialize. Add a confirmed database wait during an uncommitted write, many-way contention and a worker exit before commit. |
| Durable write intent and physical retries | `ExecutionStore.propose` seals original intent before dispatch. `GraphRuntime.dispatch` writes a new attempt row for each dispatch and uses the same logical identity on retry. | `test_concurrent_retry_safety_over_protocol`, `test_execution_lock_prevents_concurrent_duplicate`, agent and attribution restart suites | A journal attempt does not certify commit. A stalled call can leave unavailable completion evidence. |
| Response lost after commit | Existing agent retry and receipt reuse are exercised through a real write followed by injected response loss or process exit. | `test_hard_restart_after_eligible_committed_write_preserves_attribution`; `tests/agent/crash_worker.py` | A successful retry response and provider delivery are different claims. |
| Receipt and mutation reconciliation | `evaluation/reconciliation.py` matches scoped keys, canonical request hashes, receipt state, audit transitions and final state. The evaluator adds version-specific attribution rules. | `tests/evaluation/test_reconciliation.py`, `tests/remediation17/test_attribution.py` | Historical scoring stays frozen. Missing or contradictory evidence must remain explicit in any new operational projection. |
| Model-input provenance | `agent/graph.py` hashes the ordered messages and tool definitions. `agent/provenance_v3.py` joins sealed requests, journal order and exposure boundaries. | `test_sealed_request_relationships`, `test_consistently_resealed_journal_must_match_decision_and_proposal` | The full input hash establishes equality. Earlier records may lack observation-level fingerprints. Local hashes do not authenticate provider execution. |
| Recovery and attribution | The graph checkpoints through PostgreSQL. A new host must match recorded configuration and sandbox incarnation. Attack attribution derives from evidence under an explicit evaluator. | `test_resume_configuration_and_reset_binding_fail_closed`, remediation 16 and 17 restart and attribution tests | Temporal eligibility cannot establish causal influence. The original scorer and report versions retain their historical semantics. |

Supported writes can establish exactly one committed business effect for matching retries that eventually commit inside the scoped PostgreSQL transaction. A denied or rolled-back operation can commit zero effects. Separate keys permit separate effects. A physical retry can occur without another model invocation.
